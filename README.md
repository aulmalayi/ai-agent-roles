# AI Agent Roles

Набор готовых специализированных системных ролей (промптов / скиллов) для управления разработкой программного обеспечения и базами знаний с помощью ИИ-ассистентов и мультиагентных систем (Claude Code, Antigravity, Cursor, Codex и др.).

---

## 📐 Архитектура ролей

Репозиторий содержит две группы ролей:

1. **Инженерные роли** — покрывают полный цикл разработки: от продуктовой концепции и архитектуры до выполнения конкретных задач в коде.
2. **Роли управления знаниями** — обеспечивают кураторство, навигацию и антидублирование в базе знаний.

```
                  ┌─────────────────────────────────┐
                  │   Senior Architect (Level 1)    │
                  │ (Концепция, Стек, Бэклог эпиков)│
                  └────────────────┬────────────────┘
                                   │
                   ┌───────────────┴───────────────┐
                   ▼                               ▼
       [ Трёхуровневая схема ]           [ Двухуровневая схема ]
 ┌─────────────────────────────────┐ ┌─────────────────────────────────┐
 │   Junior Architect (Level 2)   │ │       Architect (Level 1)       │
 │(Нарезка задач, Ревью, Handoff)  │ │ (Совмещает стратегию и ведение) │
 └────────────────┬────────────────┘ └────────────────┬────────────────┘
                  │                                   │
                  └───────────────┬───────────────────┘
                                  ▼
                  ┌─────────────────────────────────┐
                  │       Developer (Level 3)       │
                  │   (Точечное исполнение задач)   │
                  └─────────────────────────────────┘
```

## 🗂 Роли в этом репозитории

### 1. Архитектурная группа (`roles/architecture/`)

- **[architect_senior.md](roles/architecture/architect_senior.md) — Senior Architect (Level 1)**
  * **Миссия**: Верхнеуровневое планирование, удержание фокуса продукта, определение стека, архитектуры и формирование бэклога эпиков (`BACKLOG.md`).
  * **Принцип**: *"Направление и границы важнее деталей. Одно ясное решение лучше трёх гибких."*

- **[architect_junior.md](roles/architecture/architect_junior.md) — Junior Architect (Level 2)**
  * **Миссия**: Ведение конкретного проекта по бэклогу Старшего Архитектора: детальная нарезка задач для девелоперов (`tasks.md`), проведение ревью по коду, поддержка `HANDOFF.md`.
  * **Принцип**: *"Задача без критерия приёмки — не задача. Ревью по коду, а не по отчёту."*

- **[architect.md](roles/architecture/architect.md) — Architect (Универсальный Архитектор)**
  * **Миссия**: Единственный архитектор для проектов в двухуровневой схеме (Архитектор + Девелопер). Совмещает стратегические решения и операционную нарезку/ревью задач.

---

### 2. Группа разработки (`roles/development/`)

- **[developer.md](roles/development/developer.md) — Developer (Level 3)**
  * **Миссия**: Исполнитель отдельных задач по брифу Архитектора. Обязательная проверка ясности задачи до начала написания кода, строгая работа в границах брифа, самопроверка по критериям приёмки.
  * **Принцип**: *"Сначала понять, потом делать. Вопрос до начала работы дешевле переделки."*

---

### 3. Группа управления знаниями (`roles/knowledge/`)

Роли для работы с персональными и командными базами знаний (Obsidian Vault, Markdown-репозитории, внутренние wiki).

- **[librarian.md](roles/knowledge/librarian.md) — Librarian (Curator-Navigator)**
  * **Миссия**: Куратор базы знаний. Принимает входящий материал, сверяет с существующей базой (антидубль), определяет точное место и предлагает одно оптимальное действие: добавить, заменить, консолидировать, рефреймнуть или отказать.
  * **Принцип**: *"Курирование с картой, а не складирование. Сначала точность и антидубль, затем контекст и связи."*
  * **Конфигурация**: роль использует плейсхолдер `<KB>` для корня базы знаний. Routing-таблица обобщена и адаптируется под структуру конкретной базы.

## 🚀 Как использовать

### Вариант A: Трёхуровневая схема (Большие проекты)
1. Вызывается **`architect_senior.md`** — закладывает концепцию, стек и бэклог эпиков.
2. Вызывается **`architect_junior.md`** — берет эпики, режет на самодостаточные задачи с критериями приёмки.
3. Вызывается **`developer.md`** — поштучно берет задачи, выполняет и сдаёт на ревью Младшему Архитектору.

### Вариант B: Двухуровневая схема (Компактные проекты)
1. Вызывается **`architect.md`** — сразу определяет архитектуру, бэклог и нарезает задачи.
2. Вызывается **`developer.md`** — выполняет задачи по брифам.

---

### Кураторство базы знаний

База знаний (Markdown-репозиторий, Obsidian Vault и т.п.) требует отдельной дисциплины: материал не просто складывается в папку, а проходит кураторский анализ.

1. Пользователь кидает Библиотекарю ссылку, текст или файл.
2. **`librarian.md`** ищет пересечения с существующей базой, определяет: дубль ли это, замена, консолидация или новый материал.
3. Библиотекарь предлагает **одно** действие с указанием точного файла и раздела.
4. Пользователь подтверждает командой «Выполняй» — изменения применяются.
